# STM32F407IGT6 AC6 6.24 与 GCC 14.3 子项详细对比分析

## 如何读表

- 第 1~9 节的"周期/次"= 每次内核调用的 DWT 周期数，是**耗时**：**越小越好**。"GCC 相对"列的 +x% 表示 GCC 比 AC6 慢 x%（更差），-x% 表示 GCC 更快（更好）。
- 第 10 节 CoreMark 得分（迭代/秒）是**吞吐量**：唯一**越大越好**的表。
- 第 11 节外设耗时（µs）：越小越好。
- 第 12 节 Flash 字节：越小越好。

数据来源：`runs/20261111-144218-955`（每个配置 3 轮，全部通过 EEMBC CRC 校验与时长校验）。
汇总表格见 `build/comparison.md`；本报告按子项展开并给出成因分析。

## 测试条件

- STM32F407IGT6，HSE 8 MHz → PLL 168 MHz，FLASH 5WS + 预取 + 指令/数据缓存全开；代码在 Flash、数据在 SRAM1（0 等待）执行。
- 两边同为 Thumb、DSP、硬件 32 位除法、单精度 FPU、hard-float ABI；浮点乘加合并均关闭（AC6 `-ffp-contract=off`，GCC `-std=c99`）。
- 每批 32 次调用、15 批，关中断后用 DWT CYCCNT 计时；所有内核输入固定、结果经校验和验证。
- 结果完全确定性：三轮样本逐位一致，min = 中位数。
- 反汇编证据：AC6 速度档/-O3 全部展开（如 `mla ×16`、`udiv ×16 + mls ×16`），GCC 保持紧凑循环（`mla`、`udiv + mls` 各 1 条）。

## 1. 32 位乘加（mul32，256 次迭代）

| 配置 | AC6（周期/次） | GCC（周期/次） | GCC 相对 |
|---|---:|---:|---:|
| -O0 | 6461 | 8519 | +31.9% |
| -O2 | 1362 | 1827 | +34.1% |
| -O3 | 1362 | 1827 | +34.1% |
| -O2+flto | 1186 | — | — |
| -Oz/-Os | 2607 | 2093 | -19.7% |

- AC6 把循环展开 16 份（`mla ×16`），摊薄了取数与循环跳转；GCC 保持紧凑循环。
- AC6 LTO 再省 13%（1186 ≈ 4.6 周期/元素，已接近 ldr+ldr+mla 的单发射下限）。
- 体积档反差：GCC -Os 仍展开小份循环（2093），AC6 -Oz 完全不展开（2607）——AC6 对体积的取舍更激进。

## 2. 32×32→64 位乘加（mul64）

| 配置 | AC6 | GCC | GCC 相对 |
|---|---:|---:|---:|
| -O0 | 6975 | 12370 | +77.3% |
| -O2 | 1412 | 1831 | +29.7% |
| -O3 | 1412 | 1831 | +29.7% |
| -O2+flto | 1397 | — | — |
| -Oz/-Os | 3118 | 2351 | -24.6% |

- `-O0` 差距最悬殊的一项：GCC -O0 为每次乘法生成完整调用序列（`mul ×2, umull`），AC6 -O0 更紧凑。
- 高优化档 AC6 `umlal ×8 + umull ×8` 交替展开，128 位累加链组织得更好。

## 3. 无符号求商和余数（udivmod32）

| 配置 | AC6 | GCC | GCC 相对 |
|---|---:|---:|---:|
| -O0 | 9004 | 16933 | +88.1% |
| -O2 | 3512 | 4118 | +17.3% |
| -O3 | 3512 | 4118 | +17.3% |
| -O2+flto | 3523 | — | — |
| -Oz/-Os | 5150 | 4382 | -14.9% |

- 两家高优化档都合并商/余数为一条 `udiv` + `mls`（旧 AC5 是 `udiv ×2`，这是换 AC6 的直接收益之一）。
- AC6 展开 ×16 后循环开销几乎消失；GCC 单份循环仍要每轮付跳转开销。
- `-O0` 的 +88% 主要来自 GCC -O0 的边界检查式展开更长。

## 4. 有符号除法（sdiv32）

| 配置 | AC6 | GCC | GCC 相对 |
|---|---:|---:|---:|
| -O0 | 8432 | 10234 | +21.4% |
| -O2 | 2887 | 3542 | +22.7% |
| -O3 | 2887 | 3542 | +22.7% |
| -O2+flto | 2870 | — | — |
| -Oz/-Os | 4322 | 4063 | -6.0% |

- 纯 `sdiv` 硬件指令（2~12 周期）主导，两者差距主要来自循环与调用开销，而非指令本身。
- 体积档 GCC -Os 反超 6%：这是 GCC 体积档少数赢面之一。

## 5. 欧几里得 GCD（gcd32，数据相关的除法循环）

| 配置 | AC6 | GCC | GCC 相对 |
|---|---:|---:|---:|
| -O0 | 89310 | 97208 | +8.8% |
| -O2 | 29660 | 43603 | +47.0% |
| -O3 | 29660 | 43603 | +47.0% |
| -O2+flto | 29646 | — | — |
| -Oz/-Os | 42480 | 48063 | +13.1% |

- 数据相关循环无法展开，差距全部来自单轮循环体的紧凑度（AC6 约 6 周期/轮 vs GCC 约 8~9 周期/轮）。
- 这是"循环体质量"差异最纯的样本：AC6 在所有档位都领先，与展开无关。

## 6. CRC-32（1024 字节逐位算法，8192 次位迭代）

| 配置 | AC6 | GCC | GCC 相对 |
|---|---:|---:|---:|
| -O0 | 221243 | 219197 | **-0.9%** |
| -O2 | 28199 | 55330 | +96.2% |
| -O3 | 28199 | 30741 | +9.0% |
| -O2+flto | 24618 | — | — |
| -Oz/-Os | 80939 | 63531 | -21.5% |

- `-O2` 的 2 倍差距是全场最悬殊项：AC6 把 8 位内循环完全展开成无分支异或链（约 3.4 周期/位），GCC 未展开（约 6.7 周期/位）。
- GCC -O3 也展开后差距缩到 9%。
- `-O0` 两者几乎持平（约 215 周期/字节的逐条解释式取指瓶颈，编译器无关）。
- 注意：此内核曾被 armclang `-flto` 合并调用导致假数据（详见 README），现数值为屏障修复后的真实结果。

## 7. 整数 FIR（256 输出 × 16 抽头，smlabb 路径）

| 配置 | AC6 | GCC | GCC 相对 |
|---|---:|---:|---:|
| -O0 | 122422 | 158777 | +29.7% |
| -O2 | 16844 | 34587 | +105.3% |
| -O3 | 16844 | **15938** | **-5.4%** |
| -O2+flto | 16970 | — | — |
| -Oz/-Os | 40479 | 30754 | -24.0% |

- `-O2` 差距超过 2 倍：AC6 用 `smlabb` 展开（DSP 乘加指令，1 次 16×16 乘加一条指令完成）。
- **GCC -O3 是 GCC 少数的反超点**（15938 < AC6 16844，快 5.4%）：GCC -O3 展开后调度质量更高。DSP 指令两家都能用，差距在调度而非能力。

## 8. 单精度 FIR（浮点，1024 次乘加）

| 配置 | AC6 | GCC | GCC 相对 |
|---|---:|---:|---:|
| -O0 | 146998 | 154681 | +5.2% |
| -O2 | 25489 | 43031 | +68.8% |
| -O3 | 25487 | 25869 | +1.5% |
| -O2+flto | **15986** | — | — |
| -Oz/-Os | 57121 | 39200 | -31.4% |

- `-O3` 之后两家打平（±1.5%）：`vmla` 链的调度空间有限。
- **AC6 LTO 是全场最快的浮点 FIR**（15986 ≈ 3.9 周期/抽头）：跨函数内联让展开窗口变大。
- 体积档 GCC -Os 大幅领先（AC6 -Oz 为省寄存器放弃了浮点累加的编排）。

## 10. EEMBC CoreMark 1.0（阶梯全景）

| 配置 | 得分（迭代/秒） | CoreMark/MHz | 单轮耗时（秒） |
|---|---:|---:|---:|
| AC6 -O3 | **480.26** | **2.86** | 20.82 |
| GCC -O3 | 442.29 | 2.63 | 22.61 |
| GCC -O2 | 411.36 | 2.45 | 24.31 |
| AC6 -O2+flto | 396.15 | 2.36 | 25.24 |
| AC6 -O2 | 395.30 | 2.35 | 25.30 |
| GCC -Os | 325.30 | 1.94 | 30.74 |
| AC6 -Oz | 320.73 | 1.91 | 31.18 |
| AC6 -O0 | 103.04 | 0.61 | 97.05 |
| GCC -O0 | 97.42 | 0.58 | 102.64 |

- AC6 从 -O2 → -O3 提升 +21.5%，GCC 仅 +7.5%：AC6 默认档保守，上限更高。
- LTO 对 AC6 CoreMark 无增益（396 ≈ 395）。
- 两家 -O0 差距 < 6%，基线质量接近。

## 11. 中断与外设实时性

| 项目 | AC6 速度档 | GCC 速度档 | 说明 |
|---|---:|---:|---|
| TIM2 中断响应（比较事件→ISR 读 CNT） | 0.179 µs | 0.179 µs | 硬件异常进入路径决定，与编译器无关 |
| TIM2 ISR 处理耗时 | **0.179 µs**（30 周期） | 0.190 µs（32 周期） | AC6 序言短 2 个周期 |
| EXTI4 回环响应 | 0.202 µs | 0.226 µs | 含 GPIO 路径 + 同步器 2 个 APB 周期 |
| EXTI4 ISR 处理耗时 | **0.042 µs** | 0.048 µs | |
| DMA 传输+完成中断 | 152.6 µs | 139.3 µs | 含 CPU 忙等轮询的总线争用（见 caveat） |
| 抖动（100 µs 周期） | 0 ~ 0.024 µs | 0 ~ 0.048 µs | 两边都无可测漏触发 |

- `-O0` 下 ISR 耗时约 0.34~0.37 µs（翻倍），响应延迟不变（0.155 µs，硬件路径）。
- DMA 行 caveat：M2M DMA 与 CPU 轮询共享 AHB 总线，"总耗时"随各家等待循环的指令组合波动（GCC 134~162 µs vs AC6 152~158 µs），不能解读为 DMA 硬件速度差异。

## 13. 结论矩阵

| 场景 | 推荐 |
|---|---|
| CoreMark/综合性能上限 | **AC6 -O3**（480.26，且内核项几乎全面领先） |
| 分支密集的规则循环（整数 FIR、矩阵乘）且在意代码体积 | GCC -O3 有单项反超（-5.4% / -6.5%） |
| 代码体积优先 | AC6 -Oz（最小 10760）或 GCC -Os（同档速度更快 6~31%） |
| 中断延迟 | 差异 ≤ 11 ns（硬件路径主导），编译器影响可忽略 |
| 调试构建 | 两者相当 |

一句话：**默认档 GCC -O2 强于 AC6 -O2（CoreMark +4%），但上限 AC6 -O3 高于 GCC -O3（+8.6%），且 AC6 在 9 个内核中 7 个明显领先**——代价是 2~3 倍的代码体积膨胀，体积敏感场景应选 AC6 -Oz 或 GCC -Os。
